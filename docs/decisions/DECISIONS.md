## ADR-001 Single-user personal tool, no redistribution — Assumed
- Phases 0–6 serve one user (Steven). No customer-facing display or redistribution of market data.
- Implication: individual data plans are acceptable after a license check; auth is single-user; no multi-tenant design.
- Keep `user_id` columns so multi-user can be added later via a new ADR.

## ADR-003 Local-first deployment — Accepted
- Phases 0–2 run on the user's Mac via Docker Compose (Postgres/Timescale, Redis, MinIO, api, worker, web).
- Cloud deployment is deferred until Phase 2 exit and needs its own ADR (provider, managed DB, secrets manager, auth, backups). The cloud budget in 02 §27.1 applies from then.
- Scheduled ingestion while the laptop sleeps is a known gap in local mode; jobs must backfill idempotently on restart.

## ADR-004 Market data sequencing — Assumed
- Build a `PriceProvider` interface first.
- First adapter: **Alpaca Market Data, Basic plan (free, IEX real-time)** for development and Phase 0 exit. `feed_status = live_single_venue`.
- **Massive** remains the canonical primary provider. Its adapter is built behind the same interface and activated only when `MASSIVE_API_KEY` exists and the license check (individual, non-redistribution use) is recorded here.
- Target activation point for Massive: before Phase 2 backtests or when consolidated quotes are needed, whichever comes first.
- Provider pricing in the specs is a 2026-10-04 snapshot; re-verify before paying.

## ADR-005 Time policy — Accepted
Store UTC (`timestamptz`) everywhere. Display Asia/Singapore by default; show America/New_York alongside for US market events, filings and earnings timestamps.

## ADR-006 Data honesty modes — Accepted
- `feed_status` enum per SPEC_ERRATA E4.
- Test fixtures are recorded real responses (`tests/fixtures/<provider>/...`, with recording date) and are tagged `fixture`.
- A global `DEMO DATA` banner appears whenever any fixture or demo source feeds a visible component.

## ADR-007 Bitemporal storage — Accepted
- Fact tables carry `effective_from` / `effective_to` (business time) and `recorded_at` / `superseded_at` (system time).
- Writes are insert-only through a repository layer; a DB trigger rejects UPDATE/DELETE on fact tables except setting `superseded_at`.
- Standard query helper: `as_of(known_at: datetime, effective_at: datetime | None)`.
- Raw provider payloads are stored in the object store with SHA-256 and linked from ingestion runs.

## ADR-008 Secrets and environment isolation — Accepted
- Local secrets in `.env` (gitignored). `.env.example` documents names only.
- `.claude/settings.json` denies Claude Code's Read tool on `.env*`. That rule does not cover Bash, so CLAUDE.md also forbids reading secrets via shell.
- No broker credentials of any kind before Phase 5. Live broker credentials only after Phase 6 gates, in a separate env file and DB schema.
- `LIVE_TRADING_ENABLED=false` is enforced in code.

## ADR-009 LLM usage — Proposed
- Provider: Anthropic API; model name from `LLM_MODEL` env, never hard-coded.
- Not on the Phase 0 critical path (Phase 0 entity extraction is rule-based with the SEC ticker dictionary).
- From Phase 3: extraction, linking, synthesis only. Every LLM call logged to a usage ledger (tokens, cost estimate, purpose, object IDs).
- Proposed cap: USD 50/month with 70/90/100% alerts and a circuit breaker.

## ADR-010 Seed universe — Accepted
`config/universe.yaml`, user-editable, kept small in Phase 0 to bound API usage. Seed tickers are for data-coverage testing, not investment views.
